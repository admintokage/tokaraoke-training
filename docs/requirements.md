# tokaraoke-training 要件定義書 v1.0

- 作成日: 2026-11-09
- ステータス: 確定（MVP 開発着手可）

---

## 1. 概要

### 1.1 目的
手持ちの楽曲ファイルからお手本ボーカルの音程を解析し、自分の歌声の音程と比較・採点しながら歌の練習ができる個人用 Web アプリを作る。

### 1.2 前提
| 項目 | 内容 |
|---|---|
| 利用者 | 自分 1 人のみ（ログイン・権限管理なし） |
| 練習端末 | PC（Windows 11）および iPhone（Safari / ホーム画面追加の PWA） |
| 解析端末 | Windows 11 PC（NVIDIA GPU なし＝CPU 処理）。解析時のみ起動 |
| 音源 | ユーザーが所有するローカル音源ファイル |
| 歌詞 | ユーザーがプレーンテキストで入力（タイミング情報なし） |
| 採点 | 音程のみで評価（リズム・ビブラート等は評価しない） |
| 開発体制 | 実装は Claude、ユーザーは動作確認と判断を担当（ユーザーの開発経験なし） |
| ホスティング | GitHub Pages（ユーザーの GitHub アカウントを使用） |

### 1.3 対象外（スコープ外）
- 複数ユーザー対応・アカウント機能
- 音源のクラウド保存・外部サービスへの送信
- YouTube 等ストリーミング音源の利用
- リズム・ビブラート・抑揚などの音程以外の評価
- 文字単位（カラオケ字幕風）の歌詞ワイプ表示 ※行単位のハイライトのみ

## 2. システム構成

```
┌─────────────────────────── Windows PC（解析時のみ起動）───────────────────────────┐
│  解析ツール (Python + Gradio, ブラウザ UI)                                         │
│   入力: 曲ファイル + 歌詞テキスト                                                 │
│   1. ボーカル分離 (Demucs)                                                       │
│   2. 音程抽出 (RMVPE) → ノート列化                                               │
│   3. 歌詞の行単位アライメント (stable-ts / Whisper)                               │
│   出力: <曲名>.tkt  → Google ドライブの所定フォルダへ保存                          │
└──────────────────────────────────────────────────────────────────────────────────┘
                     │ Google ドライブ経由で受け渡し
                     ▼
┌──────────────── 練習アプリ（PWA, GitHub Pages で配信）────────────────┐
│  PC ブラウザ / iPhone Safari（ホーム画面追加）                          │
│  .tkt 取り込み → IndexedDB に保存 → 練習・採点・録音                   │
│  ※ 曲データは端末内のみ。サーバーには一切送信しない                     │
└───────────────────────────────────────────────────────────────────────┘
```

- iPhone でマイクを使うには HTTPS が必須なので、練習アプリは GitHub Pages で配信する。配信するのはアプリ本体（HTML/JS）だけ。
- 解析ツールはサーバーとして常時稼働させない。PC 上でローカルに起動・終了する。

## 3. データ仕様：練習パッケージ（.tkt）

zip 形式。拡張子は `.tkt`。

| ファイル | 内容 |
|---|---|
| `manifest.json` | フォーマットバージョン、曲名、アーティスト、長さ、作成日時、解析ツールのバージョン |
| `accompaniment.m4a` | 伴奏（オフボーカル）。AAC 192kbps 程度 |
| `vocal.m4a` | 分離したお手本ボーカル。AAC 128kbps 程度 |
| `pitch.json` | お手本の音程。ノート列 `[{start, end, midi}]` と、表示用の生 f0 曲線（10ms 間隔、無声区間は null） |
| `lyrics.json` | 歌詞の行ごとのタイミング `[{start, end, text}]` |

- 1 曲あたりの想定サイズ: 約 8〜12MB
- `manifest.json` にフォーマットバージョンを持たせ、将来の形式変更に備える。

## 4. 機能要件

優先度: **MVP** ＝初版で必須 / **v1.1** / **v1.2** / **将来**

### 4.1 PC 解析ツール

| ID | 機能 | 詳細 | 優先度 |
|---|---|---|---|
| P1 | 起動 | `start.bat` のダブルクリックで起動し、ブラウザで UI が開く | MVP |
| P2 | 入力 | 曲ファイル（mp3 / m4a / wav / flac）のドラッグ＆ドロップ、歌詞テキストの貼り付け、曲名・アーティストの入力（ファイルのタグから自動入力） | MVP |
| P3 | ボーカル分離 | Demucs（htdemucs）でボーカルと伴奏に分離する | MVP |
| P4 | 音程抽出 | 分離ボーカルから RMVPE で f0 を抽出し、ノート列に量子化する（短すぎるノートの除去、近接ノートの結合） | MVP |
| P5 | 歌詞アライメント | 入力した歌詞の各行（空行は区切り）をボーカル音声に強制アライメントし、行ごとの開始・終了時刻を推定する | MVP |
| P6 | 進捗表示 | 処理の段階と進捗を表示する。CPU 処理なので 1 曲あたり 5〜15 分程度を想定 | MVP |
| P7 | 出力 | `.tkt` を指定フォルダ（既定: Google ドライブ内 `tokaraoke/`）に保存する | MVP |
| P8 | 簡易プレビュー | 出力前に、分離ボーカルの試聴と音程グラフを確認できる | v1.1 |
| P9 | 一括処理 | 複数曲を順番に処理する | 将来 |

### 4.2 練習アプリ

| ID | 機能 | 詳細 | 優先度 |
|---|---|---|---|
| F1 | 取り込み | ファイル選択で `.tkt` を読み込み（iPhone では「ファイル」アプリ経由で Google ドライブから）、形式を検証して IndexedDB に保存する | MVP |
| F2 | 曲ライブラリ | 曲一覧（曲名・アーティスト・長さ・ベストスコア）の表示と削除 | MVP |
| F3 | 練習画面 | 横スクロールの音程表示：お手本のノートをバーで、自分の音程を線で重ねて表示する。今の行と次の行の歌詞を表示する | MVP |
| F4 | リアルタイム音程検出 | マイク入力から AudioWorklet 上の YIN 法で f0 を検出する。表示遅延 100ms 以内 | MVP |
| F5 | 採点 | 各ノートの区間で、自分の f0 がお手本 ±50 セント以内にある時間の割合を求め、全ノートで重み付き平均して 100 点満点にする。オクターブ違いは同じ音として扱うかを設定で切り替える（既定: 同じ音として扱う） | MVP |
| F6 | 結果画面 | 総合点、歌詞の行ごとの得点、ズレの大きい区間の一覧（タップでその区間を再生） | MVP |
| F7 | 録音 | 歌唱中のマイク音声を録音し、結果画面で「自分の声＋伴奏」と「お手本ボーカル＋伴奏」を切り替えて再生できる。録音は最新 1 件のみ保持 | MVP |
| F8 | 再生操作 | 再生 / 一時停止、シーク、A-B 区間ループ（音程グラフ上で範囲指定） | MVP |
| F9 | 遅延補正 | 端末と出力機器の遅延を測定・手動調整し、録音や採点のタイミングを補正する | MVP |
| F10 | ガイドボーカル | お手本ボーカルの音量を 0〜100% で調整する | v1.1 |
| F11 | 歌詞タイミング修正 | 自動アライメントがずれた行を、再生しながらタップで打ち直す | v1.1 |
| F12 | キー変更 | ±6 半音。伴奏・ボーカル・お手本音程を一緒にずらす | v1.1 |
| F13 | テンポ変更 | 0.5〜1.0 倍。音の高さは保つ | v1.1 |
| F14 | 練習履歴 | 曲・日時・得点・区間別得点を保存し、得点推移をグラフで表示する | v1.2 |
| F15 | 録音の複数保存 | 過去の録音を残して聴き比べる | v1.2 |
| F16 | データのバックアップ | 履歴を書き出し・読み込みする | 将来 |

## 5. 非機能要件

### 5.1 性能
- マイク入力から音程表示までの遅延: 100ms 以内
- 音程検出の範囲: 70Hz〜1100Hz（男声低音〜女声高音）
- 音程表示の描画: 60fps を目標（iPhone で最低 30fps）
- `.tkt` の取り込み: 10 秒以内

### 5.2 iPhone（iOS Safari）対応
| 課題 | 対応 |
|---|---|
| マナーモードで Web Audio が無音になる | `navigator.audioSession.type = "play-and-record"` を設定する（iOS 16.4 以降） |
| 音声の再生開始には操作が必要 | 再生・録音は必ずユーザーのタップを起点に `AudioContext.resume()` する |
| AirPods 等の Bluetooth はマイク使用中に音質と遅延が悪化する | **有線イヤホンを推奨**とアプリ内で案内する。Bluetooth 使用時は F9 の遅延補正で対応する |
| マイクの自動処理で音程が乱れる | `echoCancellation` / `noiseSuppression` / `autoGainControl` を off にする |
| IndexedDB のデータが消されることがある | PWA としてホーム画面に追加する運用にし、`navigator.storage.persist()` を要求する。消えた場合はドライブの `.tkt` から取り込み直す |
| 録音形式 | MediaRecorder（iOS は audio/mp4）で録音する |
- 対応バージョン: iOS 17 以降の Safari

### 5.3 PC 対応
- Chrome / Edge 最新版

### 5.4 プライバシー・著作権
- 音源・解析データ・録音は、ユーザーの PC・iPhone・Google ドライブの中だけに置く。
- 練習アプリは外部に通信しない（アプリ本体の読み込みを除く）。アクセス解析も入れない。
- GitHub のリポジトリと Pages に音源データを含めない（`.gitignore` で除外する）。

### 5.5 使いやすさ
- 解析ツールは初回セットアップ（Python と依存ライブラリのインストール）を手順書とスクリプトで自動化し、以降はダブルクリックで使えるようにする。
- 練習アプリは片手のスマホ操作を前提に、主要ボタンを画面下部に置く。

## 10. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 分離ボーカルにコーラスやハモリが混ざり、音程抽出が乱れる | 採点の精度が落ちる | ノート化のときに外れ値を除去する。v1.1 のプレビューで確認できるようにする。将来は手動修正（F12 相当）を検討 |
| 日本語歌詞の自動アライメントがずれる | 歌詞表示がずれる | 行単位に限定して精度を確保する。v1.1 でタップによる修正（F11） |
| CPU 処理が遅い | 1 曲 10 分以上かかる場合がある | Demucs のモデル・分割設定を調整する。解析は事前のバッチ作業と割り切る |
| iOS Safari の仕様変更 | 音声やマイクが動かなくなる | M1 の段階で実機検証し、問題を早く見つける |
